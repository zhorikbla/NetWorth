# Автотесты NETWORTH

Папка `testing` — самостоятельный пакет со всеми присланными тестами API и PostgreSQL, собственной конфигурацией Vitest и зависимостями. В наборе 220 проверок. Тесты сами готовят отдельную тестовую БД и запускают backend на порту 3100.

## Подготовка

Нужны Node.js 20.19+ и локальный PostgreSQL. Docker не требуется.

Создайте отдельную базу один раз:

```bash
createdb networth_test
```

По умолчанию тесты берут подключение из `backend/.env` и заменяют имя рабочей базы на `networth_test`. При необходимости адрес можно переопределить через `TEST_DATABASE_URL`.

Важно: перед прогоном тесты полностью пересоздают схему `public`, поэтому имя базы обязано заканчиваться на `_test`. Защитная проверка не позволит случайно очистить рабочую базу.

## Запуск

Из корня репозитория:

```bash
npm test
```

Из папки `testing`:

```bash
npm test
npm run test:api
npm run test:db
npm run test:watch
```

Один файл или один баг-репорт:

```bash
npx vitest run tests/api/limits.test.js
npx vitest run -t "BR-07"
```

## Что происходит при запуске

1. Проверяется суффикс `_test` в имени базы.
2. Схема `public` тестовой базы пересоздаётся и к ней применяются миграции.
3. На порту 3100 запускается `node src/index.js` с отдельным JWT-секретом.
4. API- и DB-тесты выполняются последовательно.
5. Тестовый сервер останавливается.

Лог тестового сервера записывается в `testing/test-results/server.log` и не попадает в Git.

## Как читать результат

Актуальный полный прогон:

```text
Tests  206 passed | 14 expected fail (220)
```

- `passed` — требование выполняется;
- `expected fail` — тест воспроизводит известный дефект, отмеченный номером `[BR-..]`;
- обычный `failed` — новая регрессия, ошибка теста или проблема окружения.

Когда известный дефект исправлен, Vitest выводит `Expect test to fail`. Тогда `test.fails(...)` нужно заменить на `test(...)`, повторно прогнать набор и закрыть соответствующий баг-репорт.

## Структура

```text
tests/
  setup/config.js         подключение к тестовой БД, порт и JWT-секрет
  setup/global-setup.js   пересоздание схемы, миграции и запуск сервера
  setup/per-file.js       освобождение соединений после файла
  helpers/                общие запросы, SQL и фабрики данных
  api/*.test.js           проверки REST API
  db/schema.test.js       ограничения и каскады PostgreSQL
  db/seed.test.js         проверка prisma/seed.js
```

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TEST_DATABASE_URL` | адрес из `backend/.env` с базой `networth_test` | отдельная тестовая БД |
| `TEST_PORT` | `3100` | порт тестового сервера |

Пример явного подключения:

```bash
TEST_DATABASE_URL=postgresql://USER:PASSWORD@localhost:5432/networth_test npm test
```

Если тесты не стартуют, проверьте наличие базы `networth_test`, доступность PostgreSQL, установленные зависимости backend и testing, свободный порт 3100 и `testing/test-results/server.log`.
